## 1.3 文字答案：观测编码与欠驱动（4 分）

### （1）π → −π：直接角度 vs sin/cos（举例）

取跨越前 `θ = π − 0.01 ≈ 3.1316`，跨越后 `θ = −π + 0.01 ≈ −3.1316`。

| 编码 | 跨越前 | 跨越后 | 差值 |
|------|--------|--------|------|
| 直接用 θ | 3.1316 | −3.1316 | **≈ 6.26（假跳变）** |
| cosθ | cos(3.1316)≈−1.000 | cos(−3.1316)≈−1.000 | ≈0 |
| sinθ | sin(3.1316)≈0.0100 | sin(−3.1316)≈−0.0100 | 连续变号，无 2π 跳变 |

结论：直接输入角度会在 ±π 边界出现约 **2π** 的不连续；sin/cos 在圆周上连续，适合作为网络输入。

### （2）Acrobot 关节与驱动

- **关节数**：2（shoulder + elbow，见 `acrobot.xml`）。  
- **动作维数**：1。  
- **直接受驱动的关节**：**elbow**（`<actuator>` 里只有一个 `<motor name="elbow" joint="elbow" .../>`；shoulder 无 motor）。

## 2.1 文字答案：能量项在做什么（配你的代码截图）

- **计算**：`energy = 0.5·ω² + (1−cosθ)`（动能 + 相对底部的势能项）。  
- **塑形**：`tolerance(energy, bounds=(2.0,2.0), margin=2.0, …)` → 能量靠近目标 2.0 时给更高 `energy_reward`。  
- **入总奖励**：`+ energy_reward`（与 `3·upright`、速度/控制惩罚相加）。  
- **意图**：倒立需要先「荡」起来抬高机械能；能量项提供 shaping，降低只靠 upright 的探索难度。

## 3.2 文字答案：关键代码解释（15 分）

### （1）观测构造 — 目标信息如何进入观测

```python
# reacher_np.py → _get_obs
qpos = data.dof_pos
qvel = data.dof_vel
finger_xy = self._finger.get_pose(data)[:, :2]
to_target = self._target_xyz[:, :2] - finger_xy
return np.concatenate([qpos, to_target, qvel], axis=-1)
```

**解释：** 目标不以「单独标签」出现，而是通过 **`to_target`（末端相对目标的 xy 差）** 显式拼进观测；若 `qpos` 含 `target_x/target_y`，目标绝对位置也会间接出现在前段，但作业关心的相对信息主要是这两维差。

### （2）动作应用 — 每个分量控哪个关节

```python
# reacher_np.py → apply_action
state.data.actuator_ctrls = actions
```

结合 `reacher.xml`：`<motor name="shoulder" joint="shoulder"/>`、`<motor name="wrist" joint="wrist"/>`。  
**解释：** `actions[0]` → **shoulder** 扭矩；`actions[1]` → **wrist** 扭矩（顺序与模型 actuator 顺序一致）。

### （3）奖励计算 — 距离如何影响奖励

```python
dist = np.linalg.norm(self._target_xyz[:, :2] - finger_xy, axis=-1)
rwd = reward.tolerance(
    dist, bounds=(0.0, self._target_size), margin=self._target_size,
    value_at_margin=0.0, sigmoid="linear",
)  # target_size = 0.02
```

**解释（配合 `np/reward.py` 的 linear tolerance）：**

| 距离 dist | 奖励 |
|-----------|------|
| **∈ [0, 0.02]** | **= 1**（在 bounds 内） |
| ∈ (0.02, 0.04) | 从 1 线性降到 0 |
| **≥ 0.04** | **= 0** |

即：末端进入半径约 0.02 的成功带拿满分；再远 一个 margin（再 0.02）降到 0。

## 3.3 文字答案：思考题（10 分）

**判断：** 若观测中 **完全不含** 目标位置信息（含相对位置），策略 **不能可靠地** 到达每个回合都在变的目标。

**原因：** 目标每回合 reset 时重采样（至少 x 在变）。策略是从观测映射到动作的函数；若观测与目标无关，同一手臂状态应对不同目标时最优动作不同，但网络看不到目标，无法条件化，只能学到与目标无关的开环/平均行为，无法对任意新目标都指到。

**代码依据（逐项看观测，怎样才算「不含目标」）：**

当前 `_get_obs` = `qpos` + `to_target(2)` + `qvel`。

1. **必须去掉：`to_target` 两维**——这是末端相对目标的显式信息。  
2. **若 `qpos` 含目标滑块 `target_x`、`target_y`（XML 中有这两个 joint）**——这两维也是目标绝对位置，必须从观测中剔除（或确认 `num_dof_pos` 是否包含它们；包含则去掉对应下标）。  
3. **可保留：仅手臂的关节角、关节角速度**（以及不含目标的 finger 绝对位姿若单独存在——当前实现没有单独给 finger 绝对坐标，只有相对向量）。  

去掉上述目标相关分量后，观测才算「完全不含目标信息」；在此设定下不能可靠追到变化目标。
